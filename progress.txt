Адаптация enxbot под PHP 8
==========================

Кодовая база была написана под PHP 5.x/7.x. На PHP 8 бот падал с фатальными
ошибками в нескольких основных сценариях. Проверено на PHP 8.5.6.

Доказательства падений на исходном коде (git HEAD 68fc7d6)
----------------------------------------------------------

1. functions.php:195, getHints()
   Uncaught TypeError: Cannot access offset of type string on string
   Открытая подсказка записывалась в $hints[$n] строкой, а читалась как
   $hint[text]. В PHP 7 это был Warning, в PHP 8 - фатальная ошибка.
   Воспроизведено на фикстуре страницы движка с открытой подсказкой.
   Ломало /hints, cron.php и daemon.php.

2. bot.php:341, /game codes stat
   Uncaught Error: Undefined constant "cnt"
   $total += $row[cnt] - неопределённая константа вне строки.

3. functions.php:849, apiRequestPOST()
   Uncaught ValueError: curl_setopt(): Disabling safe uploads is no longer
   supported. Ломало любую отправку файла: /screenshot, /getscreens.

4. functions.php:992-1004, encrypt()/decrypt()
   Call to undefined function mcrypt_get_iv_size().
   Расширение mcrypt удалено в PHP 7.2. Ломало /encrypt и /game pass.

Что сделано
-----------

Удалённые и устаревшие API:
* mcrypt -> openssl. Формат: base64(IV[16] . AES-256-CBC(данные)), ключ -
  sha256 от ENCRYPTION_KEY. Blowfish не взят намеренно: BF-ECB в OpenSSL 3
  живёт в legacy-провайдере и недоступен по умолчанию (проверено локально).
* Убран curl_setopt(CURLOPT_SAFE_UPLOAD); загрузка файлов через CURLFile.
* Убран curl_close() - не имеет эффекта с PHP 8.0, устарел в 8.5.
* E_STRICT убран из error_reporting() во всех файлах (устарел в PHP 8.4).

mysqli (db.php):
* Явный mysqli_report(MYSQLI_REPORT_OFF): с PHP 8.1 mysqli по умолчанию
  бросает исключения, и поведение поменялось бы молча.
* Проверка результата подключения вместо обращения к false.
* mysqli_set_charset('utf8') вместо запроса "set names utf8". Кодировка
  оставлена utf8mb3 под существующую схему; переход на utf8mb4 - отдельная
  задача с миграцией таблиц.

Неопределённые переменные и ключи (в PHP 8 - Warning):
* Все preg_match без проверки результата обёрнуты в if; при отсутствии
  совпадения функции возвращают false или значение по умолчанию.
* getHints(): $remains и $hints инициализированы; подсказка всегда массив
  с ключом 'text'. daemon.php читает $array['hints'][N]['text'].
* getSectors(): всегда возвращает ключ 'sectors' (может быть пустым) и
  ключ 'code' у каждого сектора.
* cron.php: $sectorsDB инициализируется для каждой игры (раньше состояние
  секторов протекало между играми в одном проходе).
* daemon.php: $levels инициализирован до цикла.
* bot.php: разбор команды через explode + array_pad, $settings получает
  значения по умолчанию, список админов не теряется при подгрузке настроек
  игры из личного чата.

null в аргументы внутренних функций (deprecated с PHP 8.1):
* logMessage() читает поля апдейта через isset - Telegram не присылает
  отсутствующие поля.
* Приведение к строке перед mysqli_escape_string(), html2text(), preg_match().
* Html2Text: htmlFuncFlags получил значение по умолчанию (раньше при
  legacy-конструкторе оставался null и уходил в html_entity_decode()).

Функциональные дефекты, найденные попутно
-----------------------------------------

* getScheme() обращалась к неопределённым $domain/$gameid: сигнатура была
  ($cookies,$city,$gamepin), а вызов - ($cookies,$domain,$gameid). Схема
  не могла работать в принципе.
* parseCode(), режим геокодов: проверялись ключи latitude/longitude, а в
  комментарий подставлялись несуществующие lat/lon. Статус 4 проверял
  вообще несуществующие ключи, то есть геокоды не принимались никогда.
* parseCode(), статус 2: код экранировался дважды - в базу попадали лишние
  обратные слеши.
* parseCode(): getSectors() вызывался со старыми $settings['cookies'] даже
  после переавторизации; теперь используются актуальные куки.
* cron.php: в SQL-строке в двойных кавычках было '.time().' - литерал вместо
  подстановки. Запрос удаления устаревших таймеров всегда падал.
* bot.php, /game infochannel: значение подставлялось в SQL без кавычек, из-за
  чего @username превращался в пользовательскую переменную MySQL и писался NULL.
* bot.php, left_chat_member: проверялось поле $settings['city'], которого нет
  в схеме. Условие всегда было ложным, и настройки игры удалялись всегда.
  Заменено на проверку game_domain.
* bot.php, venue: использовался $message['id'] вместо $message['message_id'];
  заголовок venue экранировался до передачи в parseCode().
* bot.php, /keyboard со списком команд: обращение к $cmds[$i+1] за границей
  массива при нечётном числе команд.
* bot.php, /admin daemon: file_get_contents() по несуществующему pid-файлу.
  Добавлена readPid().
* daemon.php: screenshot() получал $timer['last_level_id'], которого нет в
  выборке; нужен $timer['level_id'].
* set_setting(): существование настройки определялось по истинности значения,
  поэтому настройка со значением '' или '0' дублировалась новой строкой.
* apiRequest(): foreach по ссылке без unset - классическая утечка ссылки.
* exec_curl_request(): обращение к error_code/description без проверки.
* Удалена мёртвая функция sendMap(): не вызывалась, была сломана
  (realpath() по URL) и содержала захардкоженный токен бота.
* Потеря игры при сбое движка. cron.php, daemon.php и parseCode() писали в
  games.last_level_id значение, полученное от getHints()/sendCode(), не
  проверяя его. При недоступном движке туда попадало -1 (или 0), после чего
  игра переставала подходить под условие выборки "last_level_id >= 0" в
  cron.php и молча выпадала из обработки до ручной правки в базе. Теперь
  значение записывается только когда оно осмысленно; -1 от sendCode()
  сохраняется намеренно, так как означает завершённую игру.
  Проверено в обе стороны: с временно снятой защитой тесты падают
  ("parseCode: стало 0", "cron.php затёр last_level_id, стало -1"),
  с защитой проходят.

Безопасность (попутно, не относится к PHP 8)
--------------------------------------------

* screenshot(): аргументы phantomjs экранируются escapeshellarg(), значения
  берутся из кук движка.
* Числовые параметры в SQL приведены через intval()/floatval() там, где
  подставлялись напрямую.
* В git-истории лежит токен Telegram-бота (удалённая sendMap). Токен нужно
  отозвать через @BotFather: удаление из рабочей копии историю не чистит.

Найдено при прогоне против encx-mock (не менялось)
--------------------------------------------------

auth() передаёт массив в CURLOPT_POSTFIELDS, поэтому логин уходит как
multipart/form-data, а не application/x-www-form-urlencoded, как отправил бы
браузер. Боевой ASP.NET-движок принимает обе формы, и бот на этом работает,
но Go в encx-mock разбирает только urlencoded и потому не видит логин и
пароль вообще.

Побочное следствие: curl на multipart добавляет Expect: 100-continue, из-за
чего в сыром ответе появляется промежуточный блок заголовков. Именно на него
опирался прежний разбор Set-Cookie через explode("\r\n\r\n", $response, 3),
бравший второй блок. Теперь заголовки собираются через CURLOPT_HEADERFUNCTION
и от наличия преамбулы не зависят.

Формат запроса намеренно оставлен прежним: коммит 68fc7d6 настраивал
авторизацию против живого движка, и смена кодировки тела рискует сломать
обход защиты от ботов. Переход, если понадобится, - это http_build_query($post)
вместо массива.

Границы проверки
----------------

* Прогон выполнен на PHP 8.5.6 - это самая строгая версия ветки 8.x, набор
  deprecation'ов в ней накопительный, поэтому чистый прогон на 8.5 покрывает
  и 8.0-8.4 по части диагностик. Запуска на 8.0 не было: Docker в системе
  не работает, отдельную версию PHP в систему не ставил.
  Риск использования синтаксиса или функций новее 8.0 закрыт статической
  проверкой в tests/check_removed_api.php.
* Заглушка движка написана по регулярным выражениям самого бота, поэтому
  подтверждает согласованность парсеров с самими собой, но не совпадение
  с разметкой боевого движка.
* db.sql в корне репозитория отстал от кода: в нём нет таблиц settings,
  codes, codeslog, locations, geocache, directionscache и колонки
  games.infochannel. Файл намеренно не трогал, полная схема - в
  tests/schema.sql.


Бэкпорт функционала из дозорного бота
====================================

Источник: приватный Telegram-бот для игры "Дозор" (PHP 7.4, mysqli).

Дозорный бот функционально богаче, но инженерно слабее: нет тестов, PHP 7.4,
db.sql разошёлся с кодом, есть заметные баги. Переносился функционал, а не код:
каждая фича переписана под текущую архитектуру enxbot (PHP 8, PDO/SQLite,
encx-биндинги) и покрыта тестами.

Что перенесено
--------------

Миграции схемы (db.php, db.sql)
* db_migrate_columns(): недостающие колонки досоздаются через ALTER TABLE по
  PRAGMA table_info. Раньше схема применялась только через CREATE TABLE IF NOT
  EXISTS, то есть добавить колонку в существующую базу было нечем.
* Новые таблицы messages, coords; новые колонки games.shtab_id,
  codes.code_type (1 метка / 2 бонус), codes.find.
* tests/schema.legacy.sql - замороженный снимок схемы до бэкпорта;
  tests/migration.php прогоняет миграцию на старой базе и проверяет, что данные
  не потеряны, а повторный прогон идемпотентен.

Модель прав доступа (functions.php, bot.php)
* Раньше прав не было вообще: любой участник чата мог сделать /game delete.
* botAdmins(), isBotAdmin(), chatMemberStatus(), canManageGame(). Право есть у
  ADMIN_USERNAME, у записей таблицы admins и у администраторов/создателя чата
  по getChatMember.
* Управляющие подкоманды /game закрыты, читающие команды остались открыты всем.
* /encrypt теперь работает только в личке: в группе шифртекст равносилен паролю.

Подкоманды /game
* shtab - штабной чат. Настройки ищутся по chat_id ИЛИ shtab_id, поэтому
  команды из штаба работают в контексте боевой игры. В дозорном боте эта ветка
  печатала в подтверждении инфоканал вместо штаба - здесь исправлено.
* url, chatid - быстрые ссылки и идентификатор чата.
* restart - сброс игры с сохранением чата и его настроек.
* delete стал каскадным: games, timers, codes, codeslog, locations, settings,
  messages, coords. Раньше чистились только games и timers.
* Введена переменная $game_chat_id: SQL адресует строку игры, а не чат, из
  которого пришла команда. Без этого команда из штаба или из лички правила бы
  чужую строку.

Бонусы (functions.php, cron.php, bot.php)
* getBonuses() читает Bonuses из GameModel.
* Команды !нбко/!всебко/!збко и латинские алиасы /obhl, /allbhl, /cbhl, /бко.
* cron синхронизирует бонусы наравне с секторами и сообщает о взятом через
  движок бонусе. Метки и бонусы разделены по codes.code_type.
* Важное отличие Encounter от Дозора: ответ на сектор и ответ на бонус - разные
  поля формы. Игрок присылает просто код, поэтому sendCode() при непринятом
  секторном коде повторяет попытку через sendBonusCode(). Без этого взять бонус
  через бота было невозможно в принципе.

Меню настроек (functions.php, bot.php)
* Было две кнопки, стало семь: noprefix, nocomment, megadzr, optimize_chat,
  pinnedtochannel, KOtoinfochannel, autoscheme. settingsToggles() - единый
  источник и для клавиатуры, и для обработчика.
* Нажатие обновляет меню через editMessageText на месте.
* callback_data подписана HMAC на ENCRYPTION_KEY. Дозорный бот шифровал её
  Blowfish-ECB; повторить это через текущий encrypt() нельзя: AES-256-CBC с IV
  даёт ровно 64 байта - жёсткий предел Telegram, без запаса, а payload длиннее
  31 байта даёт 88 байт и Telegram отклоняет кнопку целиком. Подпись даёт то же
  свойство при 30 байтах.

Самоочистка чата (optimize_chat)
* sendChatList() удаляет предыдущее сообщение того же типа перед отправкой
  нового. У каждого из девяти типов списков свой ключ last_*_message_id.
  В дозорном боте три ключа были перепутаны копипастой - здесь не воспроизведено.
* Раньше "удаление" делалось через editMessageText на "...", то есть сообщение
  оставалось в чате.

Отметка найденной метки (?N)
* markSectorFound() ставит codes.find для метки, найденной в поле без кода.
* markFoundSectors() переносит признак в списки, formatCodeList() помечает
  такие метки отдельно. Номера не выдумываются: отметить можно только метку,
  о которой уже известно от движка.

Режим megadzr
* Любое число из трёх и более цифр считается кодом. Заодно убран костыль с
  двойной проверкой регулярки безпрефиксного ввода.

Прочее
* mb_strtolower вместо strtolower при разборе команды: раньше кириллические
  команды в верхнем регистре не распознавались.
* Пересылка закрепов в инфоканал стала опциональной (pinnedtochannel).

Что осознанно НЕ перенесено (согласовано с пользователем)
--------------------------------------------------------

* Слой rich-сообщений (prepareTelegramRichMessageRequest и подмена sendMessage
  на sendRichMessage). Метода sendRichMessage нет в публичном Bot API, а
  кастомные теги (<details>, <table>, <tg-map>, <h2>) не проходят обычный
  parse_mode=HTML. Перенос рисковал молча сломать всю отправку сообщений.
* Telegram Payments: /donate, /purchase, sendInvoice, pre_checkout_query,
  successful_payment, платный доступ по games.payment. Из enxbot ранее уже был
  намеренно удалён paygate.php.
* Приём кодов по SMS (Huawei HiLink) и по радио Meshtastic (LoRa): требуют
  железа и веб-сервера, которых в enxbot нет.
* Распознавание кодов с фотографий через Google Vision: нужны платные ключи и
  composer, которого в проекте нет.
* Автораспределение экипажей (calculate_directions) и роли капитан/координатор/
  пилот из внешнего трекера через /game integration: внешней системы нет.
* Дозор-специфика без аналога в Encounter: приквелы, лиги, lite-режим,
  captain_session, errcode_to_text (словарь кодов возврата движка Дозора),
  спойлеры, режим brutespoiler.

Дозорные баги, не воспроизведённые при переносе
-----------------------------------------------

* daemon.php:146 - перезапись $result внутри while($row = fetch($result))
  прерывает цикл по играм после первой; при нескольких активных играх
  обрабатывалась только одна.
* cron.php:97 - preg_match(..., $mathes), а используется $matches.
* daemon.php:65 - ссылка на схему собиралась с необъявленной $city.
* process_update.php:1198,1312,1455 - три списка сохраняли чужой
  last_ohl_message_id вместо своего ключа.
* process_update.php:368 - вызов mysql_escape_string(), удалённой в PHP 7.
* process_update.php:1617 - подстановка username в SQL без экранирования.

Вторая часть бэкпорта
---------------------

Точки на местности (functions.php, bot.php)
* addPoint(), listPoints(), closePoint(), pointDistance(), locationTypeName().
  Статусы точки: от поля (1), свободна (2), в работе (3), закрыта (4).
* /setpoint - поставить точку (штаб и администраторы), /listpoint - список со
  статусами, /closepoint - закрыть указанную или ближайшую открытую точку.
* Присланная игроком геометка (venue) теперь попадает в тот же список: таблица
  locations перестала быть write-only.
* Автораспределение экипажей не переносилось: роли приходят из внешнего
  трекера, которого в enxbot нет (согласовано с пользователем).

Координаты (functions.php)
* getCoordsFromText() переписана: вместо эвристики strlen($lat)<5 требуется
  дробная часть (координату от "Уровень 1 из 3" отличает именно она), а
  диапазоны широты и долготы проверяются явно числами.
* Ссылки навигации больше не ведут на сторонний редиректор bots.svk.su -
  строятся прямые ссылки на Яндекс.Карты и Google Maps.
* publishCoords() собрал в одном месте пять почти одинаковых блоков публикации
  координат, которые были размазаны по bot.php и daemon.php.
* saveLevelPoint()/lastLevelPoint()/routeSummary(): при АПе к первой точке
  нового уровня добавляется перегон от точки предыдущего - расстояние и время
  в пути. Функция navi() перестала быть мёртвым кодом.
* Адрес маршрутизатора вынесен в ROUTER_URL по образцу GEOCODER_URL, иначе
  ветку было нечем проверить.

Демон (daemon.php)
* publishLevelCodes() при АПе выдаёт в инфоканал коды завершившегося уровня
  из своей таблицы codes (настройка KOtoinfochannel). Из движка их взять уже
  нельзя: он к этому моменту переключился на новый уровень.
* publishScheme() присылает схему дохода при АПе (настройка autoscheme).
* Невалидный токен Telegram больше не роняет вечный цикл необработанным
  исключением: демон пишет внятное сообщение, убирает pid-файл и выходит.

Cron (cron.php)
* Блокировка получила время старта и PID. Протухшая (по умолчанию 5 минут,
  ENXBOT_CRON_LOCK_TIMEOUT) снимается автоматически. Снятие переведено на
  register_shutdown_function, поэтому падение больше не вешает cron навсегда.
  Костыль принудительного сброса cron_running из docker-entrypoint.sh не нужен.
* publishNewOrgMessages(): сообщения организаторов публикуются в чат и
  инфоканал по одному разу, дедупликация по тексту через таблицу messages.
* Автоостановка игры по двум независимым признакам: движок сообщил о
  завершении (Event = 6) либо в чате нет активности дольше ENXBOT_IDLE_TIMEOUT.
  Признак неактивности считается по своей таблице log и работает даже когда
  движок недоступен; недоступность движка сама по себе игру не останавливает.
* Предупреждения за 15 и 5 минут больше не привязаны к окну (14;15] и (4;5].
  Порог считается пройденным, как только осталось меньше, а отметка о выдаче
  не даёт повторов. В дозорном боте пропуск прогона cron терял предупреждение
  молча; отметки убираются вместе с таймерами.

Polling (polling.php)
* Прогрессивная задержка sleep(min(retryDelay * errorCount, 30)) со сбросом
  счётчика после успешного цикла.
* Каждые 5 неуспешных циклов подряд - переподключение к БД.
* Невалидный токен (HTTP 401) перехватывается и в polling, и в cron, и в
  демоне: раньше исключение оставалось необработанным.

Веб-карта точек (map.php)
* Файла не было вовсе, при этом bot.php уже давал на него ссылку - команда
  /game codes map вела в никуда.
* Доступ подписан: mapToken() на ENCRYPTION_KEY, без корректного токена

Docker build: проверено после того, как демон стал доступен
-------------------------------------------------------------

Демон Docker поднялся в ходе этой же сессии, и сборка вскрыла реальный баг
в Dockerfile (существовавший ДО бэкпорта, не внесённый им): строка

    RUN /usr/local/bin/enxbot-screenshot --version \ \
        && mkdir -p /data /app/screens \

содержала лишний обратный слэш перед переносом строки. Docker склеивает
RUN-инструкцию в одну shell-команду, и последовательность "\ " (обратный
слэш + пробел) экранирует пробел вместо переноса строки - в результате
screenshot-runner.py получал вместо одного аргумента --version несколько
токенов, проверка `sys.argv[1:] == ["--version"]` не срабатывала, скрипт
проваливался в render() и падал с ValueError. Лишний слэш убран.

После исправления: `docker build .` проходит успешно; внутри собранного
образа `/usr/local/bin/enxbot-screenshot --version` отвечает версией
Chromium с кодом выхода 0; `config.php` внутри образа подтверждает, что
PHANTOMJS по умолчанию указывает на этот же путь.

Полный прогон контейнера (`docker run` с фиктивным BOT_TOKEN) вскрыл второй
баг - уже в самом бэкпорте (US-013): вызов apiRequest('deleteWebhook', ...)
в polling.php перед основным циклом не был обёрнут в try/catch, и невалидный
токен приводил к Uncaught TelegramUnauthorizedException вместо внятного
выхода. cron.php и daemon.php эту ветку уже перехватывали (register_shutdown_
function и общий try/catch), а вот вызов до входа в цикл polling.php остался
неприкрытым. Исправлено: тем же try/catch, что и внутри цикла, с exit(2) и
сообщением в STDERR/error_log. Полный прогон tests/run.sh (183 проверки) и
повторная сборка образа после исправления - зелёные; контейнер с фиктивным
токеном теперь падает предсказуемо (exit 2, сообщение о невалидном токене)
вместо Fatal error.
